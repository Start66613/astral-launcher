# Astral Launcher · 自研 Minecraft 启动器方案书

> 版本 v0.1 · 2026-10-22
> 目标：在 PCL 收缩功能的时间窗口里，做一款「界面/动效/自定义」明显越级、并以 DeepSeek 为大脑的启动器。
> 本文只回答三件事：**做什么、用哪套技术做、先做哪一步**。代码从下一阶段开始。

## 1. 背景：PCL 到底发生了什么

先把事实和传闻分开，因为**这决定了我们的产品边界**。

**已确认的事实**

- 2026-10-20，PCL 推送 `2.99.0.0` 正式版（仓库 commit `6b9a50d`，作者 LTCat）。更新说明写明：为遵守相关法律法规，**不再提供 Minecraft 的下载功能**，并特别声明此事与网易、微软及游戏原作方无关。
- 几乎同一时间，HMCL 等国内第三方启动器也陆续调整了下载相关服务。
- 影响面：**已安装的版本仍可正常启动**；受影响的是「下载新版本」「导入新整合包」这类需要分发游戏本体的入口。

**社群传闻（未经官方证实）**

- 起因是某未成年人在私服充值，家长维权时把涉事私服和 PCL 一并举报。截至本文写作，没有监管部门的正式通报。

**真正的原因（比传闻更重要）**

Minecraft 国际版在国内没有版号。第三方启动器提供「游戏本体下载」，等于在分发一个未过审的境外游戏客户端——这件事本身就是灰色地带，举报只是**提前引爆**。换句话说：**任何以「帮你下载 MC 本体」为核心卖点的启动器，都在同一个风险敞口上。** 我们不能把产品命脉建在这上面。

> 产品含义：把「下载」让给官方渠道，把「启动 / 管理 / 诊断 / 洞察 / 个性化」留给自己。这不是妥协，反而是差异化的起点——因为 PCL 现在恰恰把这些入口砍掉了一部分，而用户在意的从来不只是下载。

参考：[网易号报道](https://www.163.com/dy/article/L9PF7ILM0519RE6Q.html)、[MCBBS 讨论](https://bbs.mcmod.cn/forum.php?mod=viewthread&tid=24121)

## 2. 从 PCL 源码读到的 8 件事

仓库：`Meloong-Git/PCL`（8.5k stars，170MB，语言标记 **Visual Basic .NET**，全量 XAML）。以下结论都基于仓库文件结构与体积，可作为我们架构决策的输入。

| # | 观察 | 证据 | 对我们的启示 |
|---|---|---|---|
| 1 | **技术栈是 VB.NET + WPF**，Win 独占 | 全仓 `.xaml` + `.vb`，`Plain Craft Launcher 2.vbproj` | 它的 UI 天花板 = WPF 天花板。我们要在观感上越级，换栈比改栈便宜 |
| 2 | **所有控件都是自绘的** | `Controls/` 下 30+ 个：`MyButton`、`MyCard`、`MyListItem`、`MyLoading`、`MySlider`、`MyScrollBar`、`MyDropShadow`… | PCL 的「统一观感」是靠重写每一颗控件换来的，成本极高。新栈要做的是**让主题化成为默认能力**，而不是逐个控件改 |
| 3 | **主题 = 一份资源字典** | `Resources/Custom.xaml`（27KB）+ `Images/Themes/` | 证明「运行时换肤」可行，但只到颜色/背景图级别 |
| 4 | **个性化设置页很薄** | `Pages/PageSetup/PageSetupUI.xaml`（36KB） | 用户能调的只有配色、背景、字体、动画开关。**布局与组件级自定义是空白——这正是我们的切入口** |
| 5 | **页面是左右分栏 + 单窗口切换** | `Pages/PageLaunch/PageLaunchLeft|Right`、`PageInstance`、`PageDownload`… | 导航模型简单可靠，值得沿用；但可以升级为「可拖拽卡片栅格」 |
| 6 | **启动逻辑极重** | `ModLaunch.vb` 122KB、`ModMinecraft.vb` 115KB | 版本隔离、JVM 参数、依赖库、authlib-injector、登录链……这部分**不要重新发明**，用成熟库或严格照规范实现 |
| 7 | **PCL 自带规则式崩溃分析** | `ModCrash.vb`（77KB）、`ModWatcher.vb`（20KB） | 说明「崩溃分析」是刚需且 PCL 已经验证过。但它做的是**规则匹配**；AI 补的正是规则覆盖不到的长尾 |
| 8 | **单文件自包含分发** | 仓库根目录 `最新正式版.zip`（2.6MB） | 用户对「下载即用、无运行时依赖」有强预期，选型时要计入体积成本 |

**由此得到的设计原则**

1. **不要 fork。** 见第 3 节，法律上走不通，工程上是继承 10 年技术债。
2. **核心抄思想、不抄代码**：分层（Base / Minecraft / Resource / UI）、任务系统、日志监听、规则库——这些是模式，可以独立实现。
3. **UI 层必须是我方可完全掌控的新栈**，否则「界面高度自定义」永远做不深。
4. **崩溃分析要做「规则 + AI」双层**：规则零成本、确定性强；AI 覆盖长尾。单靠 AI 会有幻觉，单靠规则覆盖不全。

## 3. 四条硬约束

### 3.1 许可证：PCL 不是开源软件

`LICENCE` 文件写得很清楚：《PCL 分发有限许可》+《PCL 存储库合理使用指南》。核心规则：

- **轻度使用**（只参考极小部分，或做的东西与 PCL 实质功能不重复）→ 允许，但**必须署名**，且**不得让用户误以为与 PCL 有关**（点名禁止 `Potato Craft Launcher`、`PCL 手机版` 这类命名）。
- **重度使用**（改仓库、参考大量内容、功能重叠）→ 名称必须以 `Plain Craft Launcher (PCL)` 开头，并标注为第三方修改版；同时点名禁止 `PCL 3`、`PCL++`、`PCL Pro` 等。

**结论：我们可以读它的代码学架构，但不能 fork 改皮发布，也不能叫任何像 PCL 的名字。** 如果只是「参考了它的分层思路」，属于轻度使用 → 在关于页写一句「架构思路参考 PCL」即可。

### 3.2 Mojang EULA

第三方启动器可以存在，但：不得分发游戏本体、不得绕过正版验证、必须走微软账号登录。这和第 1 节的合规结论一致。

### 3.3 不要做「绕过限制」的功能

事件之后市面上出现大量「解锁补丁」「修改版启动器」，社群已在提醒其中捆绑木马。这类东西既违法又有安全风险，**不碰**。

### 3.4 性能是体验的一部分

MC 玩家大量使用低配机/核显笔记本。启动器自己吃掉 500MB 内存和 3 秒启动时间，再漂亮的动效也是负分。所有方案都必须答出：**冷启动 < 2s、常驻内存 < 200MB、idle CPU < 1%**。

## 4. 四个方案

### 4.0 对比总表

| 维度 | A 原生自绘<br>(.NET 10 + WPF/WinUI 3) | B 跨平台自绘<br>(Avalonia 12) | **C Web 内核**<br>(Tauri 2 + Web UI) | D AI 伴侣<br>(Sidecar) |
|---|---|---|---|---|
| 语言 | C# / XAML | C# / XAML | TS/React + Rust | 任意（先 C# 或 TS） |
| 平台 | 仅 Windows | Win/mac/Linux | Win/mac/Linux | Win（跟随宿主） |
| 界面自由度 | 中（要自绘控件） | 高（样式系统强） | **极高**（CSS/Canvas/WebGL） | 低（只是面板） |
| 动效能力 | 中（Storyboard/Composition） | 高（Transitions/KeyFrames） | **极高**（Framer Motion/Lottie/着色器） | 中 |
| 主题深度 | 颜色/背景 | 颜色/样式/模板 | **任意（CSS 即主题）** | 跟随宿主 |

| 冷启动 | 快 | 快 | 中（WebView 初始化） | 快 |

| 首版人力 | ~20 人周 | ~16 人周 | **~12 人周** | ~2 人周 |

### 4.1 方案 A：原生自绘（.NET 10 + WPF 深度改造 / WinUI 3）

**定位**：最像 PCL 的路线，用同一套技术把 PCL 没做好的事做好。

**技术栈**
- .NET 10（LTS）+ WPF（自绘控件体系）或 WinUI 3 + Windows App SDK
- 核库：`CmlLib.Core`（MIT，.NET，支持原版/Fabric/Forge/NeoForge/Quilt + 微软登录）
- 自研：主题引擎、动效层、AI 客户端

**UI / 动画怎么做**
- WPF：`Storyboard` + `RenderTransform` + 自定义 `ControlTemplate`；用 `CompositionTarget.Rendering` 做帧同步
- WinUI 3：`Composition API`（`Visual`/`ImplicitAnimation`/`ExpressionAnimation`）+ `ConnectedAnimation` 共享元素过渡 + Mica/Acrylic 材质
- 动效上限：能做出「丝滑」，但做不出「炫」——粒子、着色器背景、复杂弹性曲线会很痛苦

**高度自定义**
- 资源字典热替换（换 `Theme.xaml` 即换肤）
- 布局 = 硬编码 + 有限的显隐开关；要做到拖拽栅格，需要自己写布局引擎（约 +3 人周）

**AI**
- 同一套 HTTP 客户端，无差别

**优点**：体积小、性能好、单文件分发、C#/WPF 团队直接上手、和 PCL 的坑位一一对应（知道哪些地方会踩雷）
**缺点**：**UI 是短板**。要超过 PCL 的观感，等于要重写 30 个控件再多写 30 个——这正是 PCL 花了几年做的事
**适合**：团队只有 C#、明确只要 Windows、把「稳定省资源」排在「好看」前面

---

### 4.2 方案 B：跨平台自绘（Avalonia 12）

**定位**：用现代自绘框架拿到「接近 Web 的自由度 + 原生的性能」，一套代码三平台。

**技术栈**
- Avalonia 12（已发布 12.0/12.1）+ .NET 10 + C#
- 核库：`CmlLib.Core`（同上）
- UI：自研 Design System（Token → 控件模板 → 组合）

**UI / 动画怎么做**
- `Style` / `ControlTheme` / `Selector` 体系，本质上是一套「像 CSS 的 XAML」
- 动效：`Transitions`（隐式过渡）、`Animation`（关键帧）、`RenderTransform` + `RenderOptions.BitmapInterpolationMode`
- 可用 `SkiaSharp` 自定义绘制（`Control.Render`）做圆角阴影、模糊、渐变描边
- 上限：能做出非常接近 Web 的观感，复杂着色器背景要靠 Skia 手写

**高度自定义**
- 主题包 = 一份 `Tokens.json` + 若干 `ControlTheme.axaml`，运行时热重载
- 布局插槽需要自己写（比方案 C 贵，但比方案 A 便宜）

**AI**：无差别

**优点**：单语言、跨平台、体积小、性能接近原生、样式系统足够深
**缺点**：生态与中文资料比 WPF/Web 少；复杂视觉效果仍要手写；跨平台意味着要处理三套系统集成（托盘/通知/文件关联）
**适合**：想一次做三平台、团队是 C#、且愿意为「自绘」多投入 3~4 人周

---

### 4.3 方案 C：Web 内核（Tauri 2 + Web UI）★推荐

**定位**：把「界面/动效/自定义」当成核心竞争力，用前端生态直接买到三年的 UI 积累。

**技术栈**

```
┌──────────────────────────────────────────────┐
│  WebView2 (Win) / WKWebView (mac) / WebKitGTK │
│  ┌────────────────────────────────────────┐  │
│  │ React 19 + TS + Tailwind + Framer Motion│  │
│  │ Zustand(状态) · TanStack Query(数据)    │  │
│  │ PixiJS / CSS Shader（背景特效，可选）    │  │
│  └────────────────────────────────────────┘  │
├──────────────────────────────────────────────┤
│  Tauri 2 (Rust)                              │
│  ├─ 启动器核心：版本解析 / 类加载 / 进程管理   │
│  ├─ Java 探测与 JRE 管理（Adoptium API）      │
│  ├─ 文件系统 / 压缩包 / 哈希校验（多线程）     │
│  ├─ 日志监听（tail + 结构化）                 │
│  └─ AI 网关（流式、重试、缓存、脱敏）          │
└──────────────────────────────────────────────┘
```

- 核库二选一：Rust 侧自研（约 3~4 人周，可控性最高）或先用 Node 侧 `minecraft-launcher-core` 跑通（MIT），再逐步下沉到 Rust
- 打包：Tauri bundler → MSI/NSIS，Win 上依赖系统自带 WebView2（Win10 1803+ 预装/可静默装）

**UI / 动画怎么做（这是选它的理由）**
- 主题 = CSS 变量 + `data-theme` 属性，切换零成本、可热重载
- 动效 = Framer Motion（弹簧物理、布局动画 `layoutId`、`AnimatePresence` 退场）+ View Transitions API 做页面级共享元素
- 背景特效 = Canvas2D/WebGL（`three`/`ogl`）+ CSS `backdrop-filter`
- 布局 = **JSON 描述的卡片栅格**，`react-grid-layout` 直接支持拖拽/缩放/持久化
- 上限：**没有上限**。社区里所有「好看的桌面应用」长什么样，我们就能做成什么样

**高度自定义**
- 主题包 = 一个 zip（`manifest.json` + `tokens.json` + `layout.json` + `assets/` + 可选 `theme.css`）
- 用户能改到：颜色/字体/圆角/材质/背景/图标包/**布局**/**动效曲线**/**音效**
- 社区市场：主题包上传 → 审核 → 一键应用；`theme.css` 走沙箱（只允许自定义属性，不允许 `@import`/`url()` 外链）

**AI**
- AI 网关放 Rust 侧：密钥进 Windows Credential Manager（DPAPI），前端拿不到明文
- 流式 SSE → 前端逐字渲染 + 结构化卡片同步出现

**优点**：**开发最快、观感最好、自定义最深、招人最容易**；前端生态（图表、动画、图标、组件）全部免费拿来
**缺点**：内存偏高（150~220MB）；冷启动多 200~400ms（WebView 初始化）；需要处理「Web 与原生」的边界（拖拽文件、托盘、开机自启）
**适合**：把「界面」当卖点、团队有前端能力、能接受中等资源占用

**针对缺点的对策**
- 冷启动：先渲染"壳"（本地 HTML，无网络），首帧 300ms 内可见；核心数据异步填
- 内存：不用重型图表库，图表用 SVG 手写或 `uPlot`（~40KB）；关闭时 `window.destroy()`
- 原生边界：所有系统调用走统一的 `invoke` 封装，前端零直连

---

### 4.4 方案 D：AI 伴侣（Sidecar）★先做

**定位**：不做启动器，做「PCL/HMCL/官方启动器的 AI 附加层」。1~2 周出成果，用来验证「AI 诊断」到底是不是刚需。

**形态**
- 独立小窗（或托盘常驻），监听 `.minecraft/logs/latest.log` 与 `crash-reports/`
- 游戏退出/崩溃时自动弹出诊断卡片，一键执行修复
- 也可以做成 PCL 的「外挂工具」——PCL 有自定义事件/外部工具机制，可以挂上去

**为什么先做它**
1. **法律风险≈0**：不启动游戏、不分发内容，和 PCL 的功能不重叠
2. **开发量极小**：一个日志监听 + 一个 DeepSeek 调用 + 一个结果面板
3. **能拿到真实反馈**：用户到底会不会点「分析」？愿意为它付费吗？——这个答案决定主线要不要重投 AI
4. **可复用**：诊断管线、规则库、提示词、UI 卡片，全部能平移进主线方案

**风险**：受宿主限制（拿不到启动参数时诊断会打折）；用户多装一个软件的意愿低。

---

### 4.5 已否决：直接 fork 现成开源启动器

- **PCL**：自定义许可证，禁止改皮发布（见 3.1）
- **HMCL**：GPLv3，传染性；Java/JavaFX 技术栈，UI 一样难改
- **Prism/MultiMC**：GPLv3 + Qt/C++，改 UI 的成本高于重写

结论：省下的 4 周核心开发，会在「改不动的 UI」和「许可证」上十倍还回去。

## 5. 界面系统设计（重点）

> 用户的原话是「现在太单调了」。单调不是因为颜色少，而是因为**信息密度低 + 没有层次 + 没有生命感**。下面三件事分别解决这三点。

### 5.1 三个视觉方向（同一套组件，三套皮肤）

| 方向 | 关键词 | 适用人群 | 实现要点 |
|---|---|---|---|
| **Glass 玻璃极简** | 大圆角 20px、磨砂、封面取色、缓慢视差 | 大众/日常 | `backdrop-filter: blur(24px)` + 从封面提取主色（ColorThief）驱动强调色 |
| **Pixel 像素复古** | 8px 网格、像素字体、硬阴影、扫描线、方块化转场 | 老玩家/情怀 | `steps()` 缓动做「跳帧」感 + `image-rendering: pixelated` + 8-bit 音效 |
| **Neon 霓虹赛博** | 深色、辉光、渐变描边、粒子背景、磁吸光斑 | 年轻/直播 | WebGL 粒子 + `mix-blend-mode` + 指针跟随的径向高光 |

三者共享同一套 Token 与布局引擎，**换肤 = 换一个 JSON**。这本身就是「高度自定义」的活广告。

### 5.2 五层自定义模型

| 层级 | 用户能改什么 | 难度 | 谁会用 |
|---|---|---|---|
| **L1 一键** | 明/暗、强调色、圆角档位、动效强度 | 点一下 | 90% 用户 |
| **L2 主题包** | 字体、材质、阴影、图标包、背景（图/视频/着色器） | 导入 zip | 30% |
| **L3 布局** | 卡片增删、拖拽、缩放、插槽内容替换 | 拖拽 | 15% |
| **L4 动效** | 曲线、时长、开关、音效、悬停反馈 | 滑杆 | 5% |
| **L5 数据源** | 自定义卡片：RSS / 服务器状态 / B 站粉丝数 / 自己写的 Web 组件 | 写 JSON/组件 | 1%（但传播力最强） |

**关键设计：布局是数据，不是代码。**

```jsonc
// layout.json
{
  "version": 2,
  "grid": { "cols": 12, "rowHeight": 72, "gap": 16 },
  "cards": [
    { "id": "hero",     "slot": "hero",      "x": 0, "y": 0, "w": 8, "h": 3 },
    { "id": "instances","slot": "instance-grid","x": 0, "y": 3, "w": 8, "h": 4 },
    { "id": "ai",       "slot": "ai-panel",  "x": 8, "y": 0, "w": 4, "h": 7 },
    { "id": "stats",    "slot": "stats",     "x": 0, "y": 7, "w": 12, "h": 2 }
  ]
}
```

插槽（slot）由我们提供实现，用户只负责摆位置和选内容。这样既安全（不给用户执行任意代码的能力），又足够自由。

**再加一层「场景预设」**（这是 PCL 完全没有的）：
- 日常模式：Hero + 实例 + AI + 统计
- 直播模式：大封面 + 弹幕占位 + 隐藏 mod 列表（防泄露）
- 竞技模式：一键 PvP 参数（视距/粒子/准星）+ 服务器列表前置
- 创作模式：建筑/红石工具箱 + 截图管理 + 存档快照

### 5.3 动效规范（Motion Spec）

不要「为了炫而动」。原则：**进快出慢、只动 transform/opacity、同屏并行 ≤3 个、120–240ms 是感知甜区。**

| 场景 | 时长 | 曲线 | 备注 |
|---|---|---|---|
| 页面切换 | 220ms | `cubic-bezier(.22,1,.36,1)` | 带方向性 + 共享元素（整合包图标 → 详情页） |
| 卡片入场 | 280ms（stagger 40ms） | 弹簧 `stiffness 260 / damping 28` | 只动 `transform`+`opacity` |
| 按钮按压 | 90ms | `ease-out` | `scale(.97)` |
| 弹窗 | 180ms 进 / 120ms 出 | 弹簧 | 背景 blur 从 0 → 24px 递增 |
| 悬停高光 | 120ms | `ease` | 径向渐变跟随指针（spotlight） |
| 进度数字 | 400ms | `ease-out` | 数字滚动，不用逐帧重绘 |
| 骨架屏 → 内容 | 交叉淡入 160ms | `ease` | 固定高度防布局跳动 |

**性能预算（写进 CI）**

| 指标 | 目标 | 降级策略 |
|---|---|---|
| 首帧可见 | < 300ms | 本地壳优先渲染，数据后填 |
| 冷启动 → 可交互 | < 2s | 延迟加载非首屏模块 |
| 动画帧率 | 60fps（最低 50） | 连续 3 帧掉帧 → 自动降级为淡入淡出 |
| idle CPU | < 1% | 后台窗口暂停所有动画（`IntersectionObserver` + `visibilitychange`） |
| 常驻内存 | < 220MB | 关闭页面即卸载图表/着色器 |
| 无 WebGL2 | 静态背景 + CSS 动画 | 启动时探测能力分级 |

**无障碍与体感**
- 尊重 `prefers-reduced-motion`：动效降级为瞬时切换
- 提供动效速度倍率 0.5x / 1x / 1.5x / 关闭
- 所有交互可键盘完成；焦点环可见；对比度 ≥ 4.5:1

### 5.4 首屏信息架构（解决「单调」的直接答案）

```
┌──────┬────────────────────────────────────────────┬──────────────┐
│      │  Hero：当前实例 大封面 / 视差 / 一键启动      │              │
│ Rail │  「继续冒险」最近存档 · 游玩时长 · 上次退出    │   AI 面板     │
│      ├────────────────────────────────────────────┤  （可折叠）   │
│ 首页 │  实例卡片网格（封面取色 / 悬停抬升 / 进度环）  │              │
│ 实例 │────────────────────────────────────────────│  · 崩溃诊断   │
│ 资源 │  数据洞察：本周游玩 / 死亡热点 / 进度树        │  · 日志问答   │
│ 设置 │────────────────────────────────────────────│  · 一键修复   │
```

比 PCL 多的三件事：**封面即身份**（每个实例有自己的视觉）、**数据有形状**（不只是列表）、**AI 常驻**（不是藏起来的按钮）。

## 6. AI 系统设计（重点）

### 6.1 分层架构

```
采集层  日志 / 崩溃报告 / hs_err / mod 列表 / 启动参数 / 系统信息
  ↓
本地层  解析 → 脱敏 → 模板聚类 → 规则匹配（命中即返回，0 成本）
  ↓
检索层  本地知识库（历史案例）+ 可选 RAG（Wiki/Modrinth 元数据）
  ↓
模型层  DeepSeek（结构化输出 + 工具调用），失败可降级本地小模型
  ↓
执行层  可执行修复动作（禁用 mod / 换 Java / 调参数），带预演与回滚
  ↓
反馈层  用户「解决了 / 没解决」→ 写回本地库 → 同类问题下次零成本
```

**为什么必须双层**：纯规则覆盖不全（长尾太多），纯 AI 会幻觉（编造不存在的 mod 或参数）。规则负责「确定性」，AI 负责「解释与联想」。

### 6.2 崩溃分析管线（6 步）

1. **采集**：`logs/latest.log`、`crash-reports/crash-*.txt`、`hs_err_pid*.log`、`mods/` 文件清单（名+大小+sha1 前缀）、`launcher_profiles.json`、Java 版本、GPU/驱动、内存、启动参数
2. **脱敏（本地完成）**：绝对路径 → `<GAME_DIR>`；用户名/IP/UUID/token → 占位符；**发送前给用户看「将要发送的内容」预览**
3. **聚类**：同一堆栈出现 N 次 → 折叠成 1 条 + `count: N`（一份 8MB 日志常能压到 30KB）
4. **规则前置**（命中即结束，不花 token）：
   - `java.lang.NoClassDefFoundError: net/minecraft/...` → 版本/映射不符
   - `Mixin apply failed` / `MixinTransformerError` → mod 冲突
   - `Duplicate mod` / `Missing dependency` → 依赖问题
   - `java.lang.OutOfMemoryError` → 堆内存
   - `EXCEPTION_ACCESS_VIOLATION` + `hs_err` → 显卡驱动/OpenGL
   - `Unsupported class file major version` → Java 版本过高
   - `Pixel format not accelerated` → 驱动/软件渲染
5. **模型分析**（只处理规则未命中的部分）：用 `deepseek-flash` + JSON mode，强制结构化输出
6. **执行**：把修复建议变成**动作**，不是文字

**结构化输出契约**（前端直接渲染，避免"AI 说了一堆话"）

```jsonc
{
  "severity": "fatal",                 // info | warn | fatal
  "summary": "OptiFine 与 Embeddium 同时加载导致渲染管线冲突",
  "confidence": 0.86,
  "evidence": [
    { "source": "latest.log:1284", "snippet": "Mixin apply failed ... optifine" }
  ],
  "root_cause": "两个渲染优化 mod 都修改了同一批 Minecraft 类",
  "fixes": [
    {
      "id": "disable-optifine",
      "title": "禁用 OptiFine，改用 Embeddium + Oculus",
      "risk": "low",                  // low | medium | high
      "actions": [{ "op": "disableMod", "file": "OptiFine_1.20.1_HD_U_I6.jar" }],
      "verify": "重新启动，若仍崩溃请附上新日志"
    }
  ],
  "related_mods": ["embeddium", "oculus"],
  "needs_human": false
}
```

**执行层的安全闸门**
- `low`：直接执行（禁用 mod、改配置），自动快照
- `medium`：弹 diff 预览，用户确认
- `high`：只出方案，不自动执行
- 任何动作都能**一键回滚**（快照存在 `.astral/snapshots/`）

### 6.3 数据分析（玩家真正会晒的东西）

| 数据源 | 能算出什么 | 呈现 |
|---|---|---|
| `saves/*/stats/*.json` | 行走距离、挖掘/放置方块、击杀、游戏时长 | 年度报告（类 Spotify Wrapped） |
| `saves/*/advancements/*.json` | 进度完成度、卡在哪个成就 | 进度树 + 「你差 1 个就通关」 |
| `logs/*.log.gz`（历史） | 每次会话时长、崩溃频率、卡顿次数 | 时间轴热力图 |
| `options.txt` | 视距/粒子/帧率上限 | 「你的设置正在浪费 40% 性能」 |
| `mods/` | 整合包构成、mod 数量、是否重复功能 | 功能重叠检测（两个小地图/两个 JEI） |
| 我们自己的会话记录 | 精确的启动耗时、JVM 参数与 FPS 相关性 | 「换 G1GC 后你平均 +12 FPS」 |

**注意**：这些都是本地文件，**默认不上传**。只有用户点「生成报告」才把聚合后的数字发给模型。

### 6.4 Agent 化操作（差异化最强的一点）

自然语言 → 计划 → 预览 → 执行：

> 用户：「帮我配一个 1.20.1 的 Forge 整合包，要暮色森林 + 光影，电脑是 16G 内存」

1. 解析意图（模型 → 结构化查询）
2. 调 Modrinth/CurseForge API 检索（**工具调用**，不是模型编造）
3. 生成安装计划：版本 / 加载器 / mod 清单 / JVM 参数 / 光影包
4. 展示 diff 与体积/风险
5. 用户确认 → 执行 → 报告结果

这里的关键是**模型只做决策，不做事实**：所有版本号、下载地址、依赖关系都来自 API，模型只负责编排。

### 6.5 成本测算（按 2026-10 DeepSeek 官方价）

当前可选模型：`deepseek-flash`（V4.1-Flash，1M 上下文，支持图像理解）与 `deepseek-v4-pro`（1M 上下文）。价格单位：元/百万 tokens，**空闲时段 = 高峰时段的一半**（高峰为北京时间工作日 9–12、14–18）。

| 场景 | 输入 | 输出 | flash 空闲 | flash 高峰 | pro 空闲 |
|---|---|---|---|---|---|
| 崩溃诊断（常规） | 8K | 1.5K | **≈0.014 元** | ≈0.028 元 | ≈0.056 元 |
| 数据洞察报告 | 20K | 3K | ≈0.032 元 | ≈0.064 元 | ≈0.13 元 |
| Agent 配包（多轮+工具） | 30K | 5K | ≈0.05 元 | ≈0.10 元 | ≈0.20 元 |

**结论：单次诊断成本约 1~3 分钱。** 1000 个用户每天各诊断一次，月成本 ≈ 420 元。

**省钱的三招**
1. **提示词前缀缓存**：system prompt + 规则库固定在消息最前 → 命中缓存后输入单价降到 1/50（0.02 元/M）
2. **规则前置**：常见崩溃不调模型，直接 0 成本返回
3. **模型路由**：常规走 flash，疑难/high severity 才升 pro；批量报告放到空闲时段跑

### 6.6 隐私与密钥

- **BYOK 模式**（推荐起步）：用户自填 DeepSeek Key，存 Windows Credential Manager（DPAPI 加密），前端永不接触明文
- **托管模式**（后期）：自家后端做 Key 池 + 限流 + 成本上限 + 内容审核，客户端只拿短期 token
- **本地模式**：接 Ollama / llama.cpp，完全离线（诊断质量下降，但隐私满分）
- **透明度**：每次请求显示「将发送 N 条日志 / 预计 X 分钱」；提供「只发骨架不发全文」开关
- **红线**：不发送账号 token、不发送 `.minecraft` 外的文件、不上传存档

## 8. 风险清单

| 风险 | 影响 | 对策 |
|---|---|---|
| **微软登录接入复杂** | 无法登录正版 | 用 device code flow + 成熟库；先把离线模式跑通 |
| **AI 幻觉给出错误修复** | 玩家存档/环境被搞坏 | 规则前置 + 风险分级 + 强制快照 + 一键回滚 |
| **成本失控** | 账单爆炸 | 规则前置、前缀缓存、模型路由、单用户日限额 |
| **主题市场被投毒** | 供应链攻击 | 主题包只允许声明式配置，禁用脚本；上传审核 + 签名 |
| **WebView2 在纯净系统缺失** | 启动失败 | 引导静默安装 + 降级到"极简原生模式" |
| **合规争议重演** | 被迫下架功能 | 从一开始就不碰游戏本体分发，产品定位写进 README |
| **和 PCL 撞名/撞脸** | 法律与舆论风险 | 独立命名、独立视觉语言、关于页明确署名与区别 |
| **单人产能不足** | 半途而废 | 先做 D 验证价值，再决定是否投入 A/B/C 主线 |

## 9. 需要你拍板的 5 件事

1. **平台**：只做 Windows，还是一次做三平台？（决定 A vs B/C）
2. **团队**：你一个人，还是有前端/C# 的伙伴？（决定技术栈，不要逆着人的技能选）
3. **下载功能**：做成「导入已有游戏 + 官方渠道引导」，还是坚持要内置下载？（后者法务风险显著更高，且会重演 PCL 的剧本）
4. **AI 形态**：BYOK 免费工具，还是我们出 Key 做订阅？（决定要不要后端）
5. **社区**：要不要做主题市场/分享？（决定后端与审核投入，也是长期护城河）
