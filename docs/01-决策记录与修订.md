## 2. 技术栈定稿

**Tauri 2 + React 19 + TypeScript + Rust 核心。**

Windows-only 之后省掉的事：不用管 WebKitGTK / WKWebView 的兼容层，不用担心 Linux 的字体渲染差异；可以直接调 `ShellExecuteW`、`SHGetKnownFolderPath`、`CredWriteW`（凭据）、`SetProcessDpiAwarenessContext`。

打包只出两种：NSIS 安装包（x64）+ 免安装 zip。WebView2 在 Win11 和 Win10 1803+ 已预装，缺失时静默安装引导。

**为什么不是 WPF**（一句话，不是贬低）：原型里的 CSS 就是最终界面，改成 XAML 要整体重写一遍，排版精度还会掉；主题市场也需要 CSS 级别的表达力。**留后路**：下载 / 启动 / 分析三个核心写成独立的 Rust crate，将来想换壳（WPF / WinUI / Avalonia）不用重写业务。

## 3. 下载模块（内置，但要能「一小时下线」）

### 3.1 先把边界说清楚

会做的：

- 从 **Mojang 官方 CDN** 取全部文件：版本清单（`piston-meta`）、资源（`resources.download.minecraft.net`）、依赖库、加载器安装器（Fabric / Forge / NeoForge 官方源）
- 用**用户自己的微软账号**登录后下载；离线模式只能启动本地已存在的版本
- 国内镜像只做**透明加速**（HTTP 代理 + 缓存），不改内容、不做「资源替换」
- 全量 SHA1 校验、断点续传、失败重试、坏文件隔离

不会做的：自建游戏文件 CDN、把 jar 分发给没有账号的人、绕过正版验证、「离线登录冒充正版」、任何「解锁补丁」。

> 这不是道德表态，是产品存续条件。PCL 那次真正的教训不是「不该有下载」，而是——**它下线一个功能要发一个新版本，发版期间用户只能靠猜**。

### 3.2 远端开关（必须做，约 2 人日）

启动时和每 6 小时拉一次：

```jsonc
// GET https://cfg.astral.dev/v1/flags
{
  "download": {
    "enabled": true,
    "mode": "full",            // full | import-only
    "reason": "",
    "mirrors": ["official", "mirror-cn-1"]
  }
}
```

| 状态 | 客户端行为 |
|---|---|
| `enabled:true, mode:"full"` | 正常下载 |
| `enabled:false, mode:"import-only"` | 下载入口置灰 + 一行说明 + 「如何手动导入」帮助；**不发版** |
| 拉取失败 | 用本地缓存；首次启动默认 `true` |

再加一层保险：`import-only` 的完整版构建始终保留在 CI 里（一个开关产出的产物），真出事时直接把下载页换成导入页，**1 小时内**完成，而不是一周。

### 3.3 模块结构

```
core-download/
  meta.rs      版本清单 + inheritsFrom 继承链解析
  resolve.rs   规则求值（os/arch/features）+ classpath 拼装 + natives 解压
  fetch.rs     并发池（分块 4MB / 断点续传 / 限速 / 指数退避重试 3 次）
  verify.rs    SHA1 校验 + 坏文件隔离 + 增量补全
  mirror.rs    源优先级 + 测速选源 + 熔断（30s）
  progress.rs  统一事件流 → 前端订阅（Tauri event）
```

验收指标：装 1.20.1 全量（约 120 个文件）在 100M 宽带上 < 90 秒；断网重连续传成功率 100%；校验失败自动重下不超过 2 次。

### 3.4 UI

下载页就是原型里的第 3 张图：顶部一行状态（源 / 速度 / 队列 / 本月流量），下面版本列表，点「安装」弹一个 320px 的选项面板（加载器、安装目录、Java）。

安装过程**不弹模态框**，就在原地出进度条 + 可展开日志——这点 PCL 做对了，照抄。

## 4. 界面语言 v2：把「简约」写成 12 条硬规则

这是这次返工的核心。上一版违反的是第 1、2、10 条。

1. **只有两种颜色**：页面底色 + 卡片白。不许渐变、不许模糊、不许发光。
2. **全局一个强调色**，只出现在主按钮、选中态、链接、进度条。一屏内强调色面积 < 5%。
3. **卡片 = 1px 边框 + 白底 + 4% 投影**，圆角 8。不要「浮起来的玻璃」。
4. **只有 4 档字号**：19（页面标题）/ 13（正文）/ 12（次要）/ 11.5（辅助）。行高 1.6。
5. **间距只用 4 的倍数**：4 / 8 / 12 / 14 / 16 / 24。卡片内边距 16，卡片间距 14。
6. **图标 16px 线性**，1.7 描边，不填色，不用彩色图标。
7. **列表优先于卡片墙**：一行能说清的，不做成一块。
8. **每屏最多两个视觉层级**（标题级 + 正文级），不做第三层装饰。
9. **动效三档**：120ms（hover / 按压）、160ms（页面切换）、200ms（抽屉）。只动 `opacity` 和 `transform`。
10. **禁止清单**：粒子、视差、鼠标光斑、弹簧回弹、自动轮播、彩虹渐变、霓虹发光。
11. 数字用 `tabular-nums`，列对齐。
12. 任何装饰元素问一句：**删掉会影响理解吗？** 不会 → 删。

配色（亮色）：底 `#F3F4F6`、卡片 `#FFFFFF`、线 `#E5E7EB`、主文 `#15181D`、次文 `#5B6472`、辅助 `#8B95A3`、强调 `#2F6BED`。
暗色：底 `#15171B`、卡片 `#1C1F24`、线 `#2A2E35`、主文 `#E9EBEF`。

**自定义仍然很深**：亮/暗、4 个强调色、3 档圆角、2 档密度、动效开关——但这些都在「一个克制的一致性框架」里变，不是让你把界面变成另一个物种。主题市场的每一套皮肤，都是这 5 个变量 + 一张背景图生成的。

### 4.1 布局结构（v4 修订：两级导航）

前三版之所以显得「空」，不是配色问题，是结构问题：一条左侧导航 + 单列滚动，内容全堆在顶部，右边和下面必然留白。改成 PCL 那种两级结构后，空间自然被吃满：

```
┌─────────────────────────────────────────────────────────────┐
│ [A] Astral    启动   下载   设置   更多        AI 诊断  — □ ✕ │ 48px 强调色底
├──────────────┬──────────────────────────────────────────────┤
│ 左栏 236px    │  右区：卡片通栏，padding 18/20                │
│ 内容随标签变： │                                              │
│ · 启动 → 账号 │  列表行高 44，表单行 14/16 + 控件 ≥600 宽      │
│   + 启动按钮  │                                              │
│ · 下载 → 分类 │                                              │
│ · 设置 → 子页 │                                              │
│ · 更多 → 帮助 │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

四条布局规则：

1. **顶栏 48px，强调色底**，左侧品牌，中间四个标签，右侧 AI + 窗口控制；选中 = 白底 + 强调色文字（和 PCL 一致，一眼能认出来）。
2. **左栏固定 236px，内容随标签切换**——这是本次最大的结构改动。启动页左栏是「账号 + 启动」，且启动按钮**永远锚在底部可见**，不用滚动就能点。
3. **右区卡片一律通栏**，不设 `max-width`；列表行高 44，表单行 14/16 且控件宽 ≥600 —— 控件太窄是上一版「空」的直接原因。
4. **启动页用两栏瀑布**（左：版本 / 存档；右：公告 / 本周 / AI），底部补一条「快捷操作」，整屏填满且不堆砌。

配色也随之微调：页面底 `#F2F6FC`（带一点蓝，和强调色同源），标题栏用强调色本身（暗色模式下压成 `#21304A`），其余不变。

## 5. AI：BYOK 落地

- Key 由 Rust 侧 `CredWriteW` 写进 **Windows 凭据管理器**；前端永远只拿到「已配置 / 未配置」。
- 请求走 Rust（`reqwest` + SSE），通过 Tauri event 推给前端，避开 CORS，也避免 Key 出现在 WebView 里。
- 每次请求前显示「将发送 N 条日志 / 预计 ¥X」；默认只发**骨架**（规则命中的片段 + 模组清单），可切「全量」。
- 模型路由：默认 `deepseek-flash`；`severity=fatal` 且规则未命中时提示升级 `deepseek-v4-pro`。
- 失败降级：无 Key / 无网 → 纯规则模式，仍给出结论（AI 是增强，不是前提）。

## 6. 主题市场

- 包格式：zip = `manifest.json` + `tokens.json` + 可选 `theme.css` + `assets/`
- **禁止 JS**。`theme.css` 解析时只放行自定义属性声明，`@import` / `url()` / `expression` 一律拒绝
- 体积上限 5MB，SVG 走消毒（防 XSS），包体做签名校验
- 服务端：对象存储 + 审核队列 + 一个下载量榜。不需要账号体系，作者署名即可
- 先不做钱，做「作者署名 + 榜单」；有量了再谈分成

## 8. 风险（更新）

| 风险 | 对策 |
|---|---|
| 下载模块被举报 | 远端开关 + `import-only` 构建常驻 CI，1 小时可下线 |
| 单人 burnout | 每周只承诺一个可验收目标；做不完就砍范围，不加时长 |
| BYOK 门槛太高 | 默认走规则模式，AI 是需要时才开的增强 |
| 主题市场被投毒 | 禁 JS、CSS 白名单、体积上限、签名 |
| 微软登录接入慢 | 先做「导入已有 .minecraft + 离线启动」，登录后置 |
