## 怎么跑

```powershell
cd D:\软件开发\AstralLauncher\app

# 只跑网页（不需要 Rust，浏览器里看 UI）
pnpm dev

# 原生窗口（需要 Rust 工具链）
pnpm tauri dev

# 出 exe
pnpm tauri build
```

产物在 `src-tauri/target/release/astral.exe`（`--no-bundle` 时），
完整打包会额外产出 `src-tauri/target/release/bundle/nsis/*.exe`。

## 环境备注

- Node 用系统自带的 `C:\Program Files\nodejs`；pnpm 用 DSH 自带的 `pnpm.mjs`（`node <path> …`）
- Rust 通过 TUNA 镜像安装（官方源在国内会卡死）：`RUSTUP_DIST_SERVER=https://mirrors.tuna.tsinghua.edu.cn/rustup`
- crates 走 rsproxy 镜像，写在 `%USERPROFILE%\.cargo\config.toml`
- 首次构建要编译约 400 个 crate，约 2 分半；之后增量 10 秒级
- pnpm 的 `onlyBuiltDependencies` 已迁到 `pnpm-workspace.yaml`（pnpm 11 不再读 package.json 的 `pnpm` 字段）

## ⚠️ 一个环境坑：工作区目录里跑不起来

`astral.exe` 放在 `D:\软件开发\...` 下双击会闪退，报
`Failed to setup app: 拒绝访问 (os error 5)`。

原因不是代码：工作区目录被加了沙箱 ACL（`Everyone` 的 `DeleteSubdirectoriesAndFiles` 为 **Deny**），
WebView2 初始化时要在这个目录里做事，被拒。同一份 exe 复制到工作区外就正常。

所以成品放在 **`D:\Astral\Astral.exe`**（已验证可启动，窗口标题 `Astral`，常驻 21 MB）。
正式发布时装到 `Program Files` 或用户自选目录即可，不受影响。
