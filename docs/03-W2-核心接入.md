# W2：核心接入（直接复用开源代码）

> 2026-10-22 · 版本清单 / 安装 / 启动 全部打通

## 1. 先看许可证，这决定「能不能抄」

| 项目 | 许可证 | 能抄进我们的项目吗 | 说明 |
|---|---|---|---|
| **XMCL**（voxelum/x-minecraft-launcher） | **MIT** | ✅ 可以，需保留版权声明 | TypeScript + Electron，1666★，有完整的 `@xmcl/*` 包 |
| **Prism Launcher** | GPL-3.0 | ❌ 不行 | 抄了整包就得 GPL 开源（含我们的 UI 与 AI 模块） |
| **HMCL** | GPL-3.0 | ❌ 不行 | 同上 |
| **MultiMC / PolyMC / ATLauncher** | GPL-3.0 | ❌ 不行 | 同上 |
| **PCL** | 自定义《分发有限许可》 | ❌ 不行 | 见 00 号文档 |
| **portablemc**（Rust crate） | **Apache-2.0** | ✅ 可以，需声明 | 完整的原版 + Forge/NeoForge/Fabric/Quilt + 微软登录 + Java 自动装 |
| **open_launcher / lyceris / daedalus** | MIT / MIT-Apache | ✅ 可以 | Rust 生态里的备选件 |
| **minecraft-msa-auth** | MIT-Apache | ✅ 可以 | 微软账号 OAuth 设备码流程 |
| **mcvm_core** | GPL-3.0 | ❌ 不行 | Rust 写的，但许可是 GPL |

**结论**：「直接抄代码」在法律上只有两条路——MIT/Apache 的直接用、GPL 的只能当参考重写。
XMCL 是唯一一个 MIT 的完整启动器，Prism 这一系全是 GPL。

## 2. 为什么最后选了 portablemc 而不是 XMCL

XMCL 的 `@xmcl/core`、`@xmcl/installer` 是 **Node 库**（`fs`、流、`node:crypto`），
我们的外壳是 Tauri + WebView，前端跑不了 Node。要用就得塞一个 Node sidecar：

| 方案 | 体积 | 工作量 | 结论 |
|---|---|---|---|
| 塞 Node sidecar 跑 `@xmcl/*` | +50~80 MB，双进程 | 小 | ❌ 为了省事把体积翻 20 倍 |
| **用 `portablemc`（Rust）** | **+0 MB**（编译进 exe） | 小 | ✅ 采用 |
| 自己从零写 | 0 | 3~4 周 | 备选 |

`portablemc` 覆盖了 XMCL 核心的绝大部分能力，而且是同步 API + 事件回调，接 Tauri 很顺。

## 3. 接了什么

`src-tauri/src/core.rs`（约 200 行，其余全是 crate）：

```rust
list_versions()                       // Mojang 清单，本地缓存
install(version, dir, user, on_progress)  // 装/补全，返回可启动的 Game
launch(version, dir, user, on_progress)   // 装 + 起进程，返回 PID
```

事件翻译成前端进度（`astral://progress`）：

| portablemc 事件 | 前端 stage | 显示 |
|---|---|---|
| `LoadHierarchy` | resolve | 解析版本 1.20.1 |
| `FetchVersion` | download | 获取版本元数据 |
| `DownloadProgress { count, total_count }` | download | 下载 132/652 |
| `LoadAssets` / `LoadedAssets` | assets | 校验 749 个资源文件 |
| `LoadJvm` / `LoadedJvm` | jvm | 使用 Java 8u51 |
| `ExtractedBinaries` | done | 解压完成 |

前端 `pages/Download.tsx`：拉真实清单 → 分「正式版/预览版/远古版」→ 点安装 → 行内进度条 + 百分比 → 装完打「已安装」。浏览器里跑时自动降级成假数据并标注。

## 4. 验证结果（真机、真网络）

从工作区外运行测试二进制（原因见 02 号文档的 ACL 那节）：

```
✓ 920 个版本，最新一个是 26.4-snapshot-5

  · 解析版本 b1.7.3
  · 获取版本元数据 b1.7.3
  · 读取资源索引 pre-1.6 → 校验 749 个资源文件
  · 查找 Java 8 → 使用 Java 8u51-cacert462b08
  · 下载 652/652
  · 解压完成
✓ 安装完成，用时 25.8 秒
```

落盘结果（`%TEMP%\astral-mc-test`）：

```
assets/ bin/ jvm/ libraries/ resources/ versions/b1.7.3
2,180 个文件 · 287 MB · 含 Mojang 官方 jre-legacy
```

也就是说：**版本清单、元数据、资源索引、依赖库、Java 运行时、natives 解压，整条链路都是通的**。
选 `b1.7.3` 做冒烟是因为它没有资源索引，20 多秒能跑完；现代版本大约 200~400 MB。

## 5. 还没做的

- 界面里的「启动游戏」还是模拟进度，没接 `launch`（差一行 `invoke`，W3 一起做）
- Forge / NeoForge / Fabric 的实例创建（crate 支持，但要做实例目录与加载器选择 UI）
- 下载源切换（portablemc 默认官方 CDN，镜像要自己包一层）
- 断点续传的 UI 展示（crate 自己有重试，但没暴露「续传」状态）
