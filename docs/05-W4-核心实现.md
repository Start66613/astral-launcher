## 4. 一个环境坑：`cargo test` 起不来

本机 `cargo test --release` 生成的测试二进制**在加载期**就失败：

```
process didn't exit successfully: ...exit code: 0xc0000139, STATUS_ENTRYPOINT_NOT_FOUND
```

排查过：不是 `panic = "abort"`、不是 `lto`、不是 `chrono`；同一份 lib 编译出的
`astral.exe` 能正常跑。`cargo test`（debug）则卡在 `ring` 的 C 构建。

**对策**：关键断言放进 app 二进制，用 `--selftest` 跑（结果写 `%TEMP%\astral-selftest.log`，
退出码 = 失败数）。这样至少保证每次改动都能被真实验证，而不是只有编译通过。

后续如果修好测试环境，可以把 `selftest()` 里的断言平移到 `#[test]`（两边共用同一批函数）。

## 5. 与 UI 的对接现状

Codex 当前只调用 v1 命令（`scanVersions` / `launchVersion` / `installVersion` / `downloadTo` /
`getConfig` / `setConfig`），这些**语义完全没变**，所以它那边不用改就能继续跑。

要切到真实实例/会话，需要前端改这几处（属于共享文件，等双方确认后一起改）：

| 位置 | 现在 | 换成 |
|---|---|---|
| 首页实例列表 | `scanVersions()` → `string[]` | `list_instances()` → `Instance[]`（含 health/dirs/modsCount） |
| 启动 | `launchVersion(ver)` → PID | `start_launch(instanceId)` → Task，再 `get_active_session()` 判断是否在跑 |
| 运行态 | 只看 pid > 0 | `astral://game-exit` + `get_active_session()` |
| 存档 | 无 | `list_saves(instanceId?)` |
| 统计 | 无 | `get_stats("7d")` |
| 能力探测 | 无 | `get_api_info()`，缺 feature 就隐藏入口 |
