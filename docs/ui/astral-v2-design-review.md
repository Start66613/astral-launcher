## 状态与动效

- `startLaunch` 返回真实 Task；queued/running 展示实际 stage/label，total 未知使用非确定进度，无整体假百分比。
- Task.done 只表示进程创建；等待查询 session，不能宣布已进入游戏。
- session.state=running 才显示“游戏进程运行中”；当前核心不确认游戏窗口或主菜单。
- 匹配 instanceId+sessionId 的 game-exit 或 exited 会话才退出，旧事件不能覆盖新会话。
- 失败立即停止活动动效，保留错误与详情，复制和重试有真实操作；健康检查失败显示原因，不在 UI 改成健康。
- 刷新先订阅，再读取任务、当前版本和会话；复用现有 useInstances 与 mergeTask 的 revision/终态规则，绝不从 localStorage PID 恢复运行态。
- 三种启动效果在正式设置中均可选择，真实流程共用一个 LiveLaunch；约500ms入场不阻挡操作。任务列表显示排队/下载/校验/安装/完成/失败的实际阶段。

### 本轮取消协议与资源重试核对

已只读核对 `origin/feature/astral-v2-core@9f77843` 的 `task.rs` 和 `docs/v2/05-P0-1-任务取消与持久化.md`。`cancelling` 是 Task 的布尔字段，不是新增 state；`bootId` 标识任务来源进程。原有 mergeTask 的 revision/终态规则不变。

- UI 适配层识别带非空 `bootId` 和布尔 `cancelling` 的新任务，仅对 queued/running 提供取消按钮；旧核心任务隐藏按钮。共享 types.ts/bridge.ts 保持不变。
- `cancel_task({taskId})` 的 accepted 只显示请求已受理，按钮禁用并等待；实际 `state=cancelled` 才显示“已取消”。请求拒绝/失败保留任务并显示原因；迟到进度不能恢复终态。阶段边界才停止，已下载文件保留，不承诺中断单文件传输或关闭已启动的游戏。
- 新核心已持久化任务；重启后的 `error.code=INTERRUPTED` 展示“上次退出时未完成”。这是中断对账，不是自动续传/断点恢复。未提供的 retry_task 仍不开假重试入口。
- LiveResource 项目信息 effect 已有 `[id, retry]`，发行文件 effect 也包含 retry。新增 HTTP 503→点击“重试读取”→实际重发请求并显示成功元数据的检查，确认不是只清除错误文案。

游戏安装当前是前端串接既有安装→创建→可选Loader任务，全部 done 后重读 health 才展示完成。它不是 Rust 原子安装计划，关窗/重启后的续接和回滚仍需核心扩展。
