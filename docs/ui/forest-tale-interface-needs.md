# Forest Tale：后续 UI 对接需求（供 DSH 协调）

状态：设计输入，尚未实现，也没有向 DSH 自动发送任务。阶段一原型不调用这些接口。本文不更改 Rust、Tauri、`bridge.ts` 或共享类型；具体命令名和类型须在选定视觉方向后与 DSH 确认。

## 已检查的现有前端桥接

`app/src/lib/bridge.ts` 已导出 `scanVersions`、`getConfig`、`launchVersion`、`installVersion`、`downloadTo`、`onProgress` 等。当前 `scanVersions()` 的前端返回类型为版本 ID 数组，可复用其真实扫描结果，不能直接当作完整实例模型。

现有 `getConfig().username` 是配置值，不能据此显示微软帐号已登录或已拥有游戏。`launchVersion()` 返回 PID 后才可展示真实进程已创建；启动按钮被点击不构成启动成功。

## 首页需要的真实数据

- 实例概览：稳定 ID、显示名称、游戏版本、加载器（未知允许空）、本地路径、可用性。区分扫描中、空目录、未安装、可启动和无权限/损坏，未知状态不可默认为就绪。
- 帐号：区分未检查、未登录、离线档案、已验证的 Microsoft 帐号、凭证过期。只使用服务端/本地认证模块确认的身份，不把自填用户名展示为真实登录。
- 启动：校验中、缺文件/依赖、等待安装、准备进程、进程已创建、失败。提供可展示的错误、是否可重试及关联日志；涉及真实操作时防止重复提交。
- 收藏和最近使用：如未提供持久化记录，UI 使用明确的空状态；不生成游玩时长、最近游玩时间、模组数量或存档数量。
- 下载摘要：只有来自真实任务状态的进度、速度和完成事件才可显示。未知总大小显示不定进度，不伪造百分比。

## AI 诊断抽屉

需要由用户选择日志、先预览并脱敏、明确确认待发送内容，然后才可向其配置的模型发送。区分未选日志、读取失败、未配置服务、等待确认、分析中、成功和失败；未配置时不生成虚假诊断。日志正文不写入设计文档、截图或开发交接单。

## 协作与验收

Codex 只定义展示需要和前端状态。DSH 负责底层读取、认证、启动、下载及后端实现；共享类型、命令名、事件和依赖变更先通过用户协调。正式接入必须检验离线、无实例、权限不足、认证失败及启动失败；成功状态需有真实返回值或事件支撑。任何跨分支整合先经用户确认。
