## 2. 已经做对、V2 要继续保留的

1. **实例隔离**：托管实例 `instances/<id>/` 独立 `mods/config/saves/logs`，`--gameDir` 指向实例目录，`--assetsDir` 共享。
2. **会话与任务分离**：`Task.done` 只代表进程已创建，运行状态看 `GameSession`；退出推 `astral://game-exit`，重启按 pid 对账。
3. **任务 revision + 终态粘滞**：前端按 revision 合并，迟到帧不覆盖终态。
4. **错误编码**：`CODE|消息|细节`，legacy 命令保持人话，新命令可分支。
5. **镜像可开关**：vendor 的 portablemc 加 `mirror::map`，并发 40→6。
6. **兼容实例只读**：`managed=false` 的实例不允许改名/删除/写模组，明确返回 `UNSUPPORTED`。
7. **自检**：`astral.exe --selftest`，27 项断言，覆盖实例/任务/会话/存档/模组/加载器解析。

## 4. 必须先修的缺陷（会影响 V2 正确性）

### 4.1 取消是假的
`cancel_task` 只把 `Task.state` 置为 `cancelled` 并推事件，**后台线程仍在下载并写文件**。用户看到"已取消"，磁盘还在动。
→ 必须引入 `Arc<AtomicBool>` 取消令牌，下载循环逐块检查；取消后清理临时文件。

### 4.2 下载没有原子替换
`download_to` 直接写目标路径，中断即留下半截文件；`mods` 里的半截 jar 会被下次扫描当成正常模组。
→ 先写 `<name>.part`，校验后 `rename` 覆盖。

### 4.3 下载地址无校验
`download_to(url, ...)` 接受任意 http(s) 地址，等于把启动器变成任意文件下载器（SSRF/投毒面）。
→ 白名单：`cdn.modrinth.com`、`api.modrinth.com`、`piston-*.mojang.com`、`resources.download.minecraft.net`、`libraries.minecraft.net`、`meta.fabricmc.net`、`bmclapi2.bangbang93.com`；重定向逐跳校验；拒绝 `file://`、`data:`。

### 4.4 CSP 为空
`tauri.conf.json` 里 `security.csp = null`，WebView 可加载任意远程资源。
→ 收紧 CSP，但**必须先与 Codex 对齐允许的来源**（`cdn.modrinth.com` 的图标、字体、可能的背景图），否则界面会白。

### 4.5 实例目录未 canonicalize
`download_to` 用 `Path::file_name()` 截断文件名，但目标目录由 `instance.dir` 拼接而来，未验证结果仍在 `gameDir` 内（junction/symlink 可逃逸）。
→ 所有写入前 `canonicalize` 并做前缀检查。

### 4.6 任务重启后状态失真
任务表在内存，进程重启后旧任务消失；但若前端本地缓存过 `running`，会一直显示启动中。
→ 任务加 `bootId`，启动时把上一次 `running/queued` 一律标为 `interrupted`（新终态）。

### 4.7 `javaPath` 未消费
`instance.json` 存了 `javaPath`，`spawn` 没有把它传给 portablemc，等于设置项无效。
→ 要么接上（`set_jvm_dir`/显式 jvm 路径），要么在契约里标注"未生效"并禁 UI。

### 4.8 统计字段恒 null
`get_stats` 的 `deaths/achievements` 永远是 null（没解析 `stats/*.json`）。
→ V2 可选：解析存档统计；否则保持 null 并在文档写明。

## 6. 数据安全边界

- 用户 `.minecraft` 里已有 1.8.9 与 26.3 两个版本、以及存档/模组/光影。**任何 V2 改动都不能破坏它们。**
- 现有代码只读 `versions/`，写入仅限 `instances/` 与全局 `mods/` 等由用户显式触发的路径。
- V2 新增的整合包/资源安装必须：默认新建实例、拒绝覆盖已存在世界、失败清理临时目录。
