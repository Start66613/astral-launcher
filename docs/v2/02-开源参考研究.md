# V2 开源参考研究（阶段一·第 2 份）

> 目的：为「版本安装 / 加载器 / 光影组件 / 资源 / 整合包 / Java / 下载 / 诊断」找可借鉴的实现。
> 结论先行：**能直接借鉴代码的只有 3 家**（PCL-CE Apache-2.0、XMCL MIT、Helios MIT）；HMCL / Prism / Refract 是 GPL-3，只能读架构。

---

## 0. 许可证总表

| 项目 | 许可证 | 语言 | 规模 | 能否移植代码 |
|---|---|---|---|---|
| **PCL Community Edition** | **Apache-2.0** | C# | 104 MB · 4.8k★ | ✅ 可，需署名 |
| **XMCL** | **MIT** | TypeScript | 48 MB · 1.7k★ | ✅ 可，需保留声明 |
| **Helios Launcher** | **MIT** | JavaScript | 38 MB · 1.0k★ | ✅ 可（但它主要是 `@xmcl/*` 的分发壳） |
| HMCL | GPL-3.0 | Java | 43 MB · 10.6k★ | ❌ 只读架构 |
| Prism Launcher | GPL-3.0 | C++ | 41 MB · 10.9k★ | ❌ 只读架构 |
| Refract | GPL-3.0 | Rust | 3 MB · 42★ | ❌ 只读架构（同为 Rust，可看 API 设计） |

> ⚠️ **PCL-CE 的许可证需要谨慎**：它的上游 PCL 是自定义《分发有限许可》，PCL-CE 声明 Apache-2.0。
> 两者之间的再许可是否成立、原作者是否同意，无法从仓库判断。
> **策略**：只借鉴「数据结构与流程」，不逐行翻译它的代码；在 `THIRD_PARTY.md` 写"架构参考"，不主张代码来源。

## 1. 逐功能对照

### 1.1 版本安装流水线

| 项 | 内容 |
|---|---|
| 参考 | **XMCL** `xmcl-runtime/install/InstallService.ts`、`InstallManifestService.ts`；**PCL-CE** `Plain Craft Launcher 2/Modules/Minecraft/ModDownload.cs` |
| 可借鉴 | XMCL 把"安装"拆成 **manifest（有什么文件）→ plan（要下什么）→ execute（任务）** 三段；PCL-CE 用统一的 `LoaderTask` 串行/并行调度 |
| Astral 现状 | 只有 `start_install`：调 portablemc `install()` 一口气做完，无中间计划 |
| 需要的新接口 | `prepare_game_install(request) -> plan`、`start_game_install(planId, revision) -> Task` |
| 许可风险 | 低（两家都可引用） |

### 1.2 加载器元数据（Fabric / Quilt）

| 项 | 内容 |
|---|---|
| 参考 | **XMCL** `install/versionSelection.ts`；**HMCL** `HMCLCore/.../addon/`（只读） |
| 可借鉴 | 按 `gameVersion` 查 meta 接口拿**全部** loader 版本，再用 `stable` 标记做推荐，而不是只取第一条 |
| Astral 现状 | `loader.rs` 只解析 Fabric，返回 `recommended` + `versions`；**Quilt 完全没接** |
| 需要的新接口 | `list_loader_builds(gameVersion, kind)`，返回每个 build 的 `stability` / `publishedAt` |
| 许可风险 | 低（XML/JSON 公开接口） |

### 1.3 Forge / NeoForge

| 项 | 内容 |
|---|---|
| 参考 | **XMCL** `install/forgeVersion.ts`（最完整，MIT）；**PCL-CE** `ModLoaderType.cs` + `ModDownload.cs` 的 loader 分支 |
| 可借鉴 | ① Forge 版本来自 `maven-metadata.xml` + `promotions_slim.json`（区分 recommended/latest）；② 版本号与 MC 版本的对应要按前缀匹配（`1.20.1-47.2.0`）；③ NeoForge 1.20.1 用 `net/neoforged/forge`，1.20.2+ 才用 `net/neoforged/neoforge`；④ 安装要跑 installer jar 并解析其产出（`install_profile.json` / `version.json`） |
| Astral 现状 | 完全没有；`spawn_with` 只认 fabric/quilt，其它返回 `UNSUPPORTED` |
| 需要的新接口 | 复用 `list_loader_builds`，`kind` 增加 `forge` / `neoforge` |
| 许可风险 | 低（读公开 maven） |

### 1.4 光影支持组件（Iris / Oculus / OptiFine）

| 项 | 内容 |
|---|---|
| 参考 | **XMCL** `install/optifine.ts`（OptiFine 安装流程）；Iris/Oculus 走 Modrinth 资源即可 |
| 可借鉴 | OptiFine 需要下载官方 installer + 静默参数 + 解析输出，不是简单丢 jar；Iris 的可用性取决于「Fabric + 对应 MC 版本」 |
| Astral 现状 | 无 |
| 需要的新接口 | `get_component_catalog(gameVersion, loader)` → `{ mainLoaders, shaderSupport, optionalComponents }` |
| 许可风险 | OptiFine 是**自有分发条款**，不能打包分发；只能"用户本机下载"。Iris/Oculus 是开源 mod，走 Modrinth 正常分发 |

### 1.5 Modrinth 项目与文件

| 项 | 内容 |
|---|---|
| 参考 | **XMCL** `moddb/ModMetadataService.ts`、`findVersion` 逻辑；**Prism** `launcher/modplatform/modrinth`（只读） |
| 可借鉴 | 项目详情与版本列表分开缓存；用 `game_versions` + `loaders` 双筛选；`release/beta/alpha` 是**渠道**不是稳定性推断；依赖在 version 的 `dependencies` 里（`project_id` + `version_id` 可空） |
| Astral 现状 | 前端直连 `api.modrinth.com` 搜索；下载用 legacy `download_to`；**无项目详情、无文件列表、无依赖** |
| 需要的新接口 | `get_resource_project`、`list_resource_files`、`prepare_resource_install`、`start_resource_install` |
| 许可风险 | 低（公开 API） |

### 1.6 模组依赖

### 1.8 整合包

| 项 | 内容 |
|---|---|

### 1.9 Java

| 项 | 内容 |
|---|---|
| 参考 | **HMCL** `HMCLCore/.../java/`（版本枚举最全，只读）；**Prism** `libraries/javacheck`；**PCL-CE** `ModJava.cs` |
| 可借鉴 | 扫注册表 + 常见目录 + `JAVA_HOME`；用 `java -version` 的输出解析 major；版本要求来自 version JSON 的 `javaVersion.majorVersion` |
| Astral 现状 | portablemc 自动装 Mojang JRE；**无枚举、无校验，`javaPath` 未消费** |
| 需要的新接口 | `list_java_runtimes`、`validate_java` |
| 许可风险 | 低（思路） |

### 1.10 下载任务 / 重试 / 取消

| 项 | 内容 |
|---|---|
| 参考 | **HMCL** `download/`（多 provider + 失败切换，只读）；**PCL-CE** `ModDownload.cs` |
| 可借鉴 | 每个文件先落到 `.part`，校验后原子 rename；失败按 provider 轮换；任务整体有取消令牌 |
| Astral 现状 | portablemc 内部有重试与缓存，但**我们的 `cancel_task` 是假的**，且没有原子替换 |
| 需要的新接口 | `cancel_task` 语义改造 + `retry_task` |
| 许可风险 | 低（自研） |

### 1.11 启动状态与诊断

| 项 | 内容 |
|---|---|
| 参考 | **PCL-CE** `Modules/Minecraft/CrashAnalysis/`（规则库）、`ModWatcher.cs`；**XMCL** `install/DiagnosisCache.ts` |
| 可借鉴 | 启动后 tail 日志，按规则签名分类（Mixin 冲突/OOM/驱动/Java 版本）；规则命中优先于 AI |
| Astral 现状 | 有 `GameSession` 与 exit 事件；**无日志读取、无诊断** |
| 需要的新接口 | `list_logs`、`read_log`、`prepare_diagnosis`、`start_diagnose` |
| 许可风险 | 中（PCL-CE 规则库只借鉴分类思路，不搬词条） |

### 1.12 微软登录

| 项 | 内容 |
|---|---|
| 参考 | **XMCL** `auth/`、**HMCL** `auth/`（都只读架构） |
| 关键事实 | 需要自己的 Azure 应用注册（client_id），走 device code；**不能借用 PCL/HMCL 的 client_id** |
| Astral 现状 | 无；portablemc 有 `msa` 模块但需要 client_id |

| 许可风险 | 高（涉及微软开发者条款，需单独确认） |

## 2. 三个可以直接落到代码的结构

1. **Install Plan 三段式**（XMCL）：`manifest → plan → execute`，plan 带 `planId + revision + expiresAt`，执行前复查。
2. **Loader 版本表**（XMCL + PCL-CE）：统一 `ComponentBuild { id, kind, version, gameVersions, stability, recommended, available }`，Forge/NeoForge/Fabric/Quilt 用同一形状。
3. **下载原子化**（HMCL）：`.part → 校验 → rename`，取消时删 `.part`。

## 3. 明确不借鉴的

- Prism 的 Qt 实例模型（C++/GPL，且我们已经用 Rust 实现）。
- HMCL 的 Java 版本解析实现（GPL），只看它覆盖的目录清单。
- OptiFine 的任何再分发方案（条款不允许）。
