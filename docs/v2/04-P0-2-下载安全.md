## 1. 做了什么

新增 `src/net.rs`（约 200 行），并改造 `download_to` 命令。

### 1.1 来源白名单

```rust
pub fn check_url(raw: &str) -> Result<String, String>
```

- **只接受 `https://`**；`http://`、`file://`、`data:` 一律拒绝。
- 拒绝带 userinfo 的地址（`https://user@host/...`）——这是绕过主机校验的常见手法。
- 拒绝 IP 字面量、`localhost`、`*.local`。
- 主机必须精确匹配白名单（不做子域通配，防止 `evil.cdn.modrinth.com` 这类伪装）。

白名单（14 个）：

| 类别 | 主机 |
|---|---|
| Modrinth | `cdn.modrinth.com`、`api.modrinth.com` |
| Mojang | `piston-data.mojang.com`、`piston-metadata.mojang.com`、`launchermeta.mojang.com`、`launcher.mojang.com`、`resources.download.minecraft.net`、`libraries.minecraft.net` |
| 加载器 | `meta.fabricmc.net`、`maven.fabricmc.net`、`maven.minecraftforge.net`、`maven.neoforged.net`、`meta.quiltmc.org`、`maven.quiltmc.org` |
| 国内镜像 | `bmclapi2.bangbang93.com` |

失败统一返回 `BLOCKED_URL|下载地址被拒绝|原因`。

### 1.2 路径边界

```rust
pub fn ensure_within(root: &Path, target: &Path) -> Result<PathBuf, String>
```

- 先把 `root` 与目标父目录都 `canonicalize`，再判断前缀——**能挡住 `..` 与 junction/symlink 逃逸**。
- 父目录不存在时按需创建，文件本身允许不存在。
- 越界返回 `INVALID_PATH|目标超出允许目录`。

`download_to` 现在强制 `gameDir` 为根：实例目录、兼容实例的共享目录都必须落在它下面。

### 1.3 原子写入

```rust
pub fn download_atomic(url, dest, expected_sha1: Option<&str>, on_progress) -> Result<u64, String>
```

流程：`删旧 .part` → 下载到 `<dest>.part` → 可选 SHA1 校验 → `rename` 覆盖目标。

- 下载失败、校验不符、重命名失败：**都删除 `.part`**，不留半截文件。
- 校验不符返回 `HASH_MISMATCH|校验失败|期望…实际…`，不再靠"下载成功"推断完整。
- 进度回调保留原来的 `astral://file` 事件字段顺序，前端无需改。

## 3. 还没做的（诚实清单）

| 项 | 状态 | 说明 |
|---|---|---|
| 重定向逐跳校验 | ❌ | 目前依赖 `portablemc` 内部 reqwest 自动跟随；白名单主机若 302 到别处不会被拦。要彻底解决得换成自建 reqwest 流式下载 |
| CSP 收紧 | ⏸ | 等 Codex 给出它加载的远程域名（图标/字体/背景），否则会白屏 |
| 哈希来源 | ◐ | `download_atomic` 支持 SHA1，但 `download_to` 目前拿不到官方哈希（Modrinth 的 `hashes` 要在 P1 的文件接口里带过来） |
| 取消令牌 | ⏸ | 属于 P0-1；当前 `.part` 机制保证"取消后不会污染目标文件"，但已开始的任务仍会跑完 |

## 4. 对现有行为的影响

- 之前 `download_to` 能下任意 URL；现在只下白名单内的。**这是有意的破坏性收紧**，前端的 Modrinth 下载不受影响（`cdn.modrinth.com` 在列）。
- 下载目标从"可能写到任何地方"变成"必须在 gameDir 内"。实例目录在 `gameDir/instances/<id>/` 下，正常路径不受影响。
- 下载中若中断，目录里只会多出 `.part`，不会再出现损坏的 `.jar`。
