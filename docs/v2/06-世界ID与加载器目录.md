# P0-5 + P0-3：稳定世界 ID、加载器构建目录（已完成）

> 提交：`feat(core): 世界 ID 与四类加载器构建目录`。

---

## 1. P0-5：稳定世界 ID

```ts
interface WorldTarget {
  worldId: string;      // w_<8 位十六进制>，由目录名派生
  displayName: string;  // 目录名（不含路径）
  dir: string;
  lastModified: string;
  sizeBytes: number;
  gameVersion: string | null;  // 未解析 level.dat，恒 null
}
// list_target_worlds({ instanceId }): WorldTarget[]
```

规则：

- `worldId = "w_" + sha1(目录名)[..4 字节]`，**同名目录永远得到同一个 ID**，改名即换 ID。
- 只认带 `level.dat` 的目录——空文件夹、`saves/` 下的杂项不会出现。
- 反解只在 Rust 内部做（`worlds::resolve`），前端拿 `worldId` 回来即可，**不用拼路径**。
- 找不到对应世界时返回空/报错，**不回退到全局目录**。

为什么不用目录名当 ID：目录名可以被用户改成 `../../x`，也可以包含任意 Unicode；
用派生 ID 后，前端即使被注入也没法通过 ID 构造路径。

## 2. P0-3：四类加载器的构建列表

```ts
interface LoaderBuild {
  id: string;          // "fabric-0.16.9" / "forge-47.2.0"
  kind: "fabric" | "quilt" | "forge" | "neoforge";
  version: string;
  mcVersion: string;
  stability: "stable" | "beta" | "alpha" | "unknown";
  recommended: boolean;
  publishedAt: string | null;   // 数据源都没有发布时间，恒 null
  available: boolean;
  unavailableReason: string | null;
}
// list_loader_builds({ gameVersion, kind }): LoaderBuild[]
```

数据源：

| 加载器 | 来源 | 推荐逻辑 | 稳定性 |
|---|---|---|---|
| Fabric | `meta.fabricmc.net/v2/versions/loader/{mc}` | `stable=true` 的第一条 | 有 stable 标记 |
| Quilt | `meta.quiltmc.org/v3/versions/loader/{mc}` | 第一条 | **数据源无标记 → unknown** |
| Forge | `maven.minecraftforge.net` 的 `maven-metadata.xml` | `promotions_slim.json` 的 `{mc}-recommended` | 含 `beta`/`alpha` 字样才降级 |
| NeoForge | `maven.neoforged.net`；1.20.1 走 `net/neoforged/forge` | 最新一条 | 一律 stable（官方无标记） |

几个容易错的地方：

- **Forge 的版本号带 MC 前缀**（`1.20.1-47.2.0`），必须剥掉前缀再给前端。
- **NeoForge 的版本号不是 MC 版本**：`1.21.1` 对应 `21.1.x`，`1.20.2` 对应 `20.2.x`。
  1.20.1 是特例，走 `net/neoforged/forge` 且版本形如 `1.20.1-47.1.x`。
- **查不到 ≠ 查询失败**：查到了但为空 → 返回空数组（UI 显示"无适配"）；
  网络/解析错误 → 抛 `NETWORK`。两者不能混。
- 所有请求都过 `net::check_url` 白名单（新增 `files.minecraftforge.net`）。

旧的 `list_loaders` 仍然返回 `LoaderCatalog[]`，现在**同时包含 Fabric 与 Quilt**，
解决了 Codex 提的"Quilt 差异"。

## 4. 验证

`--selftest` 36 → **40 项，全过**，新增：

```
PASS worlds listed               只列带 level.dat 的目录
PASS world id stable             同名目录 ID 一致
PASS world resolve               ID 能反解回目录
PASS world resolve rejects unknown  未知 ID 返回 None
```

加载器的解析函数另有单元测试（`cargo test` 在 Windows 上加载失败，见 `01-核心审计.md` §5），
网络拉取没有在自检里跑，避免离线环境误报。

## 5. 给前端的接入点

1. 数据包安装的目标选择改用 `list_target_worlds`，**不要**用 `list_saves` 的目录名。
2. 安装向导的加载器下拉改用 `list_loader_builds`：能列出全部构建，
   `stability === "unknown"` 时不要显示"稳定版"徽标。
3. `available === false` 的构建置灰并显示 `unavailableReason`。
4. Forge/NeoForge 现在能选，但**安装会失败**——UI 应在选择后提示
   "该加载器安装尚未实现"，或暂时只开放 Fabric/Quilt。
