# 契约增量 v4（V2 后端第一批）

> 相对 `docs/api-contract.md` v3.3。全部是**增量**：已有命令签名不变，
> 新字段都带默认值，旧前端不会崩。

## 1. 新增命令

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `list_loader_builds` | `gameVersion, kind` | `LoaderBuild[]` | 四类加载器的**全部**构建 |
| `list_target_worlds` | `instanceId` | `WorldTarget[]` | 存档稳定 ID，数据包安装用 |

### LoaderBuild

```ts
interface LoaderBuild {
  id: string;              // "fabric-0.16.9"
  kind: "fabric" | "quilt" | "forge" | "neoforge";
  version: string;         // 已剥掉 MC 前缀（forge）
  mcVersion: string;
  stability: "stable" | "beta" | "alpha" | "unknown";
  recommended: boolean;
  publishedAt: string | null;   // 三家数据源都不给发布时间
  available: boolean;
  unavailableReason: string | null;
}
```

- 查到但无适配 → 返回 `[]`；网络/解析失败 → 抛 `NETWORK`。**两者不要混**。
- `kind` 传未知值 → `UNSUPPORTED`。
- Fabric/Quilt 可安装；**Forge/NeoForge 目前只能列、不能装**，UI 需相应禁用。

### WorldTarget

```ts
interface WorldTarget {
  worldId: string;        // w_<8 hex>，由目录名派生，稳定
  displayName: string;    // 目录名，仅供显示
  dir: string;
  lastModified: string;
  sizeBytes: number;
  gameVersion: string | null;   // 未解析 level.dat，恒 null
}
```

- 前端只能用 `worldId` 回传给安装接口，**不要用 displayName 拼路径**。
- 不存在的 `worldId` 会被拒绝，不会回退到全局目录。

## 2. Task 字段增量

```ts
interface Task {
  // …v3 字段不变…
  bootId: string;       // 产出该任务的进程启动标识
  cancelling: boolean;  // 已请求取消，等 worker 停下
}
```

- `cancel_task` 返回 `{ accepted }`；`cancelling=true` 只代表**受理**，
  `state="cancelled"` 才是真的停了。
- 取消来得太晚、活儿已干完 → 任务以 `done` 结束，`result.cancelledLate = true`。
- 启动器重启后，上次未结束的任务变 `state="error"`、`error.code="INTERRUPTED"`。
- 后台线程 panic 会被捕获，任务以 `INTERNAL` 失败，不会永远 `running`。

## 3. Session 字段增量

```ts
interface GameSession {
  // …v3 字段不变…
  reconciled: boolean;  // 重启后按 pid 对账收尾，退出码与时长不精确
}
```

`astral://game-exit` 载荷增量：

```ts
{ …, exitKnown: boolean, crashed: boolean, reconciled: boolean }
```

- `crashed` **只在退出码已知且非 0** 时为 true；`exitCode === null` 表示未知，
  此时 `exitKnown=false`，界面应显示"已结束，退出码未知"而不是崩溃。

## 4. 新增/收紧的错误码

| 码 | 场景 |
|---|---|
| `BLOCKED_URL` | 下载地址不在白名单 / 非 https / 含 userinfo / 内网地址 |
| `HASH_MISMATCH` | 下载后校验不符，`.part` 已清理 |
| `INVALID_PATH` | 目标越出允许目录 |
| `INSTANCE_EXISTS` | 创建实例时同 id 已存在，拒绝覆盖 |
| `INTERRUPTED` | 上次启动器退出时任务未结束 |
| `CANCELLED` | 任务被取消 |

## 5. 行为变更（前端需要知道）

1. **离线 UUID 变了**：改用标准的 `MD5("OfflinePlayer:<name>")`。
   已有存档若存在旧 UUID 的 `playerdata/<uuid>.dat`，该实例会继续沿用旧身份；
   **新实例/新存档使用新 UUID**。没有自动迁移。
2. **用户名必须是 3–16 位 ASCII 字母/数字/下划线**，否则 `set_config` 与
   `start_launch` 都会返回 `INVALID_NAME`。
3. `instance.json`、`config.json`、`tasks.json` 都改成原子写；
   `config.json.bak` 会在覆盖前生成。
4. 加载器安装后如果元数据写不进去，任务会失败（以前会假装成功）。

## 7. 安装计划（v4 新增）

```ts
interface GameInstallRequest {
  name: string;
  gameVersion: string;
  loader?: { kind: "fabric" | "quilt" | "forge" | "neoforge"; version: string } | null;
  memoryMb?: number;
}

interface GameInstallPlan {
  planId: string;
  revision: number;
  expiresAt: string;          // 15 分钟
  request: GameInstallRequest;
  target: { proposedInstanceId: string; displayPath: string; isolated: true };
  files: PlannedFile[];       // 目前只列"要装的东西"，明细后续补
  issues: PlanIssue[];        // blocking=true 时禁止执行
  downloadBytes: number | null;  // 未知返回 null
}

// prepare_game_install({ request }): GameInstallPlan
// start_game_install({ planId, revision }): Task   // result: { kind:"game-install", instance }
```

规则：

- `prepare` **无副作用**：不建目录、不下载、不改配置。
- 计划一次性：`start` 取走后即失效；`revision` 不匹配或过期都返回 `PLAN_EXPIRED`。
- `issues` 里 `blocking=true` 的项会阻止执行；目前会阻塞的有：
  实例名非法、官方清单里没有该版本、Forge/NeoForge（安装未实现）、内存越界、网络不可用。
- 执行顺序：补版本文件 → 建实例 → 装加载器 → 健康检查。
  任何一步失败都会**删除本次新建的实例目录**回滚，不会留下半成品。
- 健康检查不通过 → `VERIFY_FAILED`，同样回滚。
- 取消会在步骤边界生效；已完成的步骤不回滚已下载的版本文件（那是共享资源，可复用）。

## 8. Forge / NeoForge 安装（已实现，实测通过）

start_install_loader 与 start_game_install 对 orge / 
eoforge 改用官方安装器：

1. 从 maven 下载 installer jar 到 `<gameDir>/.astral/installers/`（白名单内）；
2. 确保目标目录有 `launcher_profiles.json`（安装器硬性要求，缺了会直接退出）；
3. 用找到的 Java 执行 `--installClient <gameDir>`；
4. 对比安装前后 `versions/` 差集，取新生成的版本 id（优先名字含加载器的那个）；
5. 把该 id 写进实例的 `launchVersion`，启动时直接启动它，不再走 Fabric 装配。

Java 查找顺序：`JAVA_HOME` → `<gameDir>/jvm/*/bin/java.exe` → PATH。

**实测**：1.20.1 + Forge 47.2.0，在隔离目录 `D:\Astral\forge-test` 完成真实安装，
生成 `versions/1.20.1-forge-47.2.0`（inheritsFrom 1.20.1，
mainClass=cpw.mods.bootstraplauncher.BootstrapLauncher），下载 82 个库、81.7 MB。

**未验证**：NeoForge 实装（代码路径与 Forge 相同，但未跑过真实安装）；
Forge 版本的**启动**需要先补齐 assets，本轮未做。
### 实测补充：Forge 1.20.1 启动

同一隔离目录继续真实启动 `1.20.1-forge-47.2.0`：

- 进程存活超过 60 秒（测试脚本随后主动 kill）
- `logs/latest.log` 出现渲染线程创建纹理图集、加载着色器，说明已进主菜单
- 因此 Forge 的「安装 → 启动」链路是通的

**踩到的坑（已修正判断）**：首次启动时 `piston-meta.mojang.com` 的 assets 索引
出现过一次 TLS handshake EOF。事后复测：**直连连续三次均 200**，说明是偶发网络抖动，
不是被墙，也不是代码问题。

结论与待办：
- 下载层需要**失败重试**（当前 portablemc 内部重试不足，一次抖动就会让启动失败）。
- 现有 BMCLAPI 改写覆盖 `libraries.minecraft.net` / `resources.download.minecraft.net`
  / 版本清单，未覆盖 assets 索引与客户端 jar；属于优化项，不是阻塞项。
